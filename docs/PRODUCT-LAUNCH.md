# Выход City Quest 0.7 в продукт

Архив содержит приложение и проверяемый порядок подготовки релиза. Публичный сервис, платежный оператор, магазины приложений, Kubernetes и корпоративный IdP не активируются сборкой архива. Рабочие домены, контакты, права доступа и фактические результаты приёмки заполняет владелец площадки.

## Проверка конфигурации без побочных действий

```sh
# Проверяет только локальные настройки, ничего не отправляет провайдерам.
node --env-file=/secure/.env.production scripts/production-check.mjs

# После отдельной миграции, bootstrap и настройки MFA: читает существующую БД.
node --env-file=/secure/.env.production scripts/production-check.mjs --database

# Проверяет подготовленные оператором YAML, а не пример из архива.
kubectl kustomize deploy/k8s/base > /secure/cityquest-base.yaml
kubectl kustomize deploy/k8s/cnpg > /secure/cityquest-database.yaml
node --env-file=/secure/.env.production scripts/production-check.mjs \
  --database --manifest /secure/cityquest-base.yaml --manifest /secure/cityquest-database.yaml
```

Команда выводит JSON и завершается кодом 1 при ошибке. `ok: true` означает прохождение выбранных проверок; `productionReady` всегда `false`, поскольку эта команда не принимает площадку вместо оператора. В отчёте нет значений ключей, DB URL, персональных адресов аккаунтов и исходного YAML. Ошибки подключения также не копируются в отчёт. Команда `npm run release:check` загружает `.env.enterprise`, если этот файл существует; уже заданные переменные окружения имеют приоритет. Для SQLite production или другого файла используйте показанный выше прямой вызов `node --env-file=/secure/.env.production scripts/production-check.mjs`, чтобы проверить нужную конфигурацию.

Базовый режим проверяет production-настройки, HTTPS origin без примеров, защищённые cookies, независимость ключей, отсутствие активного bootstrap-пароля, валидность policy и лимитов. Для PostgreSQL проверяются настройки TLS/pool и токен приватного мониторинга. Режимы OIDC и AI должны быть полностью настроены либо выключены. Опубликованные `SUPPORT_EMAIL`, `PRIVACY_URL`, `TERMS_URL` обязательны для релизной проверки; `BILLING_CONTACT_EMAIL` обязателен при включённом ручном выставлении счетов. Адреса документов проверяются синтаксически: доступность и содержание утверждает оператор.

`--database` никогда не создаёт БД, не применяет миграции, не добавляет пользователей или seed. В PostgreSQL чтение выполняется в repeatable-read/read-only транзакции с ограничением времени запросов; SQLite открывается read-only. Проверяются версия схемы, наличие активного администратора с MFA, активные аккаунты на зарезервированных example/test доменах, согласованность photo ledger и лимит хранения. С версии 0.8 проверяются все сохранённые MFA-секреты, сообщения питомца и cached replies: аутентификация DATA_ENCRYPTION_KEY, корректность MFA и привязка шифротекста к контексту. Обход идёт страницами по 250 записей без вывода секретов. Устаревшая схема вызывает отказ, а не автоматическую миграцию. При ошибке конфигурации соединение с БД вообще не открывается.

`--manifest` ограничивает размер каждого файла 8 МиБ, ищет известные placeholders и требует digest у всех `image` / `imageName`. Это дополнительный текстовый gate, не YAML-схема и не Kubernetes admission. Перед выпуском отдельно выполните schema validation и `kubectl apply --dry-run=server` на своей площадке. В архиве оставлены явно обозначенные примерные домены/registry/bucket; релизная проверка их отклоняет.

## Настройки продукта и ёмкости

Координаты городов, геометрия уже сохранённых клеток, уровень на 500 XP, канонический JPEG и верхние ограничения декодера — версионируемые правила данных. Менять их произвольной env-переменной нельзя без миграции и проверки совместимости. Вместо удаления всех чисел в коде v0.6 отделяет такие правила от рабочих параметров оператора.

| Параметры | По умолчанию | Назначение |
| --- | --- | --- |
| `HTTP_MAX_INFLIGHT` | 128 | Одновременные запросы на процесс; ограничение приёмки защищает память |
| `HTTP_UPLOAD_CONCURRENCY` | 2 | Одновременные загрузки фото на процесс |
| `HTTP_BODY_TIMEOUT_MS`, `HTTP_JSON_LIMIT_KB` | 15000; 64 | Срок чтения тела и размер обычного JSON; фото имеет отдельный предел |
| `HTTP_RESPONSE_TIMEOUT_MS` | 45000 | Тайм-аут простоя ответа, допустимо 1000–120000 мс; не повторяет завершённое действие |
| `PASSWORD_KDF_CONCURRENCY` | 2 | Параллельные дорогие вычисления хеша пароля |
| `RATE_LIMIT_MAX_KEYS` | 10000 | Максимальное число ключей rate limiter в общей БД |
| `PG_POOL_MAX`, `PG_POOL_QUEUE_LIMIT` | 10; 20 | Соединения и ожидания на реплику |
| `PG_CONNECTION_TIMEOUT_MS`, `PG_STATEMENT_TIMEOUT_MS`, `PG_LOCK_TIMEOUT_MS` | 5000; 15000; 5000 | Ограничения соединения, SQL-запроса и ожидания блокировки |
| `PG_IDLE_TRANSACTION_TIMEOUT_MS` | 30000 | Ограничение простаивающей транзакции |
| `PHOTO_STORAGE_LIMIT_MB`, `PHOTO_DAILY_UPLOAD_LIMIT`, `PHOTO_RETAINED_LIMIT` | 100; 5; 20 | Общий объём JPEG, успешные загрузки в UTC-сутки, снимки игрока |
| `GAME_GPS_MAX_AGE_SECONDS`, `GAME_GPS_MAX_ACCURACY_METERS` | 90; 80 | Допуск позиции для приключений и фото; не доказательство физического присутствия |
| `TERRITORY_DAILY_VISIT_LIMIT` | 10 | Суточный предел командных посещений игрока |
| `ADVENTURE_PET_XP`, `PHOTO_DISCOVERY_XP`, `PHOTO_PET_XP` | 20; 20; 10 | Только будущие начисления; исторические ledgers сохраняются |
| `PHOTO_VOTER_MIN_AGE_HOURS` | 24 | Минимальный возраст аккаунта для голоса; дополнительно требуется игровая активность |

Полные допустимые диапазоны заданы централизованными валидаторами; неверное значение вызывает отказ. Одинаковые настройки нужны всем репликам; менять награды отдельным Pod недопустимо. В HTTP/pool/декодер лимитах считается **процесс**, а storage/upload/rewards учитываются общей БД. Не умножайте число Pod без бюджета DB connections, AI quotas, CPU и памяти.

Контакты оператора отображаются только после настройки: `SUPPORT_EMAIL`, `PRIVACY_URL`, `TERMS_URL`, `BILLING_CONTACT_EMAIL`. `MAP_STYLE` выбирает стиль; внешние tile/sprite/glyph origin для него перечисляются в `MAP_RESOURCE_ORIGINS` (HTTPS, максимум 6). Тот же набор передайте при mobile build. Не вставляйте туда API keys или URL с credentials.

## Приёмка площадки

| Условие | Проверяемое свидетельство | Состояние в архиве |
| --- | --- | --- |
| Код и миграции | Автотесты и browser QA, версия/хеш архива | Фактические результаты в `VALIDATION.md` |
| Native PostgreSQL | CI с `PG_TEST_REQUIRED=true`, тесты конкурентных транзакций | Gate настроен; локальная среда не подменяет его WASM-результатом |
| Контейнер | Build, непривилегированный запуск, Sharp decoder, health/ready | CI настроен; Docker в среде подготовки не запускался |
| Домен и доступ | Реальные TLS/DNS, строгий CORS, ingress trust, SSO/MFA | Требуется ваша площадка и IdP |
| Восстановление | Backup в независимом хранилище, восстановление с ключами, сверка аудита | Процедура поставляется; RPO/RTO необходимо измерить |
| HA | Отказ процесса, DB primary и зоны, сохранение acknowledged writes | Манифесты поставляются; фактический failover не измерен |
| Нагрузка | Профиль входа, чтений, GPS, наград, фото, голосов; p95/5xx/очереди | Локальные проверки не задают production capacity |
| Контент | Доступные точки, ответственный модератор, проверенные бизнесы | OSM и редакционные задания требуют актуализации; горный пример — draft |
| Поддержка | Настоящие контакты, документы, процедура обращений и удаления | Параметры и release gate; владелец публикует содержание |
| Монетизация | Сверка платежа/возврата, условия и ответственное лицо | Ручной пилот выключен по умолчанию; native checkout отсутствует |
| Телефоны | GPS, WebGL, SSO callback, камера/галерея, сеть, logout на Android/iOS | Общий код и native проекты; подписанные APK/IPA не выпущены |

Порядок выпуска: изолированный стенд → приёмка оператора и команды → ограниченный пилот → расширение нагрузки по измерениям. Заранее зафиксируйте владельца инцидента, канал связи, допустимые RPO/RTO и решение об остановке записи. При миграции схемы планируйте окно обслуживания и заранее проверенный rollback через совместимый backup; старый образ нельзя возвращать поверх новой схемы.

Для горного задания требуются актуальная проверка доступности и публикация администратором. Фотоконкурс оценивает места голосованием сообщества; его рейтинг не является объективной оценкой красоты и не гарантирует защиту от всех Sybil-аккаунтов. Не объявляйте партнёрство с организацией только потому, что карточка присутствует в OSM.

`HTTP_RESPONSE_TIMEOUT_MS` (по умолчанию 45000 мс) ограничивает простой ответа и проходит общий валидатор конфигурации в release gate. Слот HTTP освобождается после окончания обработки и передачи ответа; обрыв клиента не освобождает ещё выполняющееся действие. Общий requestTimeout учитывает HTTP_BODY_TIMEOUT_MS. DATABASE_URL не принимает query-параметры; PGOPTIONS не используется. Тайм-ауты задаются только явными PG_* параметрами, чтобы URL не переопределял проверенную политику.

Перед обновлением установленной PWA v0.6 закройте все её вкладки и окна, затем откройте приложение снова. Старый worker не получает исправленную стратегию кеширования до активации v0.7. Проверенный после активации worker сохраняет согласованный HTML/JS одной версии. Для native-сборки заново передайте свой API origin; приведённый в архиве пример не является работающим backend.
