# Архитектура 0.2

## Развёртывание

Один процесс Node.js 24+, SQLite WAL на локальном диске, браузерный клиент того же origin. Нет production npm-зависимостей. MapLibre рисует векторную карту и здания, Three.js — игровые объекты в общем WebGL-контексте. Библиотеки включены в `public/vendor`; географические тайлы OpenFreeMap поступают по сети. Код карты сохраняет fallback CDN, разрешённый CSP. API, данные и роли проверяет сервер.

Модуль `cities.mjs` содержит рабочие прямоугольники Алматы и Астаны; это области покрытия, не административные границы. Координаты проходят проверку относительно города. При переключении клиент останавливает GPS, ждёт текущие отправки и пересоздаёт карту с соответствующим центром. Асинхронные ответы прежнего города отбрасываются по поколению запроса. В localStorage хранится выбор города, не сессия или пароль.

## Основные данные

| Таблицы | Назначение |
| --- | --- |
| users | scrypt-пароль, роль, общий XP, MFA, блокировка |
| sessions | Хеш opaque cookie, публичный ID для отзыва, сроки, активность, факт MFA |
| login_challenges / recovery_codes | Короткоживущий второй этап входа и одноразовые резервные подтверждения |
| organizations / quests | Город, владелец, модерация, координаты и версия записи; у квеста расписание, лимит, проверка |
| completions | Уникальная пара игрок/квест, выданный XP и время |
| reward_tokens | Хеш одноразового кода, создатель, срок и факт использования/отзыва |
| explored / positions | Исследованные ячейки и последняя позиция с городом |
| teams / members | Команда одного города, приглашение, участники и согласие на геопозицию |
| audit / meta | HMAC-цепочка событий и её текущая вершина, сведения об импорте/инициализации |
| rate_limits / schema_migrations | Постоянные окна ограничения запросов и применённые миграции |

`PRAGMA user_version=2`. Миграция v1 транзакционна, проверяет внешние ключи, сохраняет пользовательские данные и помечает прежние сущности городом Алматы. Старые сессии отзываются. Начальные данные Астаны имеют отдельный маркер, поэтому повторный запуск не дублирует квесты. Снимки импортируются один раз с отдельными маркерами городов.

Ячейки исследования имеют размер 0.002° × 0.0015°, то есть физический размер зависит от широты. Процент изученного города не заявляется. Последние координаты очищаются через час; пользователю доступны немедленное удаление позиции и сброс ячеек выбранного города.

## Доступ и сессии

Гость видит одобренные места и опубликованные неназначенные задания. Игрок — свой прогресс и назначенные ему задания. Бизнес управляет собственными карточками и квестами, публикация требует администратора. Назначение владельца, импорт и роли доступны администратору. Регистрация принимает только `player` и `business`.

Сессия хранится в HttpOnly/SameSite=Lax cookie; в production обязательны Secure и canonical HTTPS origin. Срок администратора — 12 часов, остальных — 7 дней, неактивность по умолчанию 30 минут. Смена роли и блокировка отзывают сессии и MFA challenges. Перед мутацией с телом JSON доступ повторно проверяется после чтения тела, чтобы отзыв сессии во время медленного запроса вступал в силу.

TOTP: 6 цифр, 30 секунд, окно ±1; использованный счётчик повторно не принимается. Секреты зашифрованы AES-256-GCM, recovery-коды хешируются и расходуются один раз. Настройка требует пароль и действующую сессию. MFA enable/disable и второй этап входа транзакционны. Challenge действует 5 минут и максимум 5 попыток; незавершённая настройка — 10 минут. Production блокирует административные операции до включения MFA. Пароль первого этапа не предоставляет доступ к уже защищённому MFA аккаунту.

Rate limits хранятся в SQLite, ключи идентификаторов хешируются. Reverse proxy доверяется только в режиме `loopback` и только при локальном peer; из X-Forwarded-For используется последний корректный адрес. JSON-записи проверяют Origin и Sec-Fetch-Site. CSP ограничивает источники скриптов, стилей, карты и соединений; тела и секреты не попадают в HTTP-логи.

## Награда как транзакция

Сервер проверяет публикацию, назначение, расписание, лимит и свежую позицию в городе квеста. Точность GPS должна быть ≤150 м; для прохождения позиция не старше 90 секунд и внутри радиуса. Для `code` проверяется общий код, для `token` — уникальный 96-битный код со сроком. Все проверки актуальной записи, расходование токена, completion, XP и аудит выполняются под одной write-транзакцией. Уникальная пара игрок/квест обеспечивает идемпотентный повтор без второго начисления.

Лимит — количество прохождений, а не денежный бюджет. Выпуск кода не резервирует награду: при достижении общего лимита остальные действующие коды больше не дают пройти квест. Прямое архивирование квеста или смена способа проверки отзывает неиспользованные коды. При снятии с публикации через модерацию организации прохождение блокируется статусом; организатор проверяет кампанию перед повторной публикацией.

Браузерный GPS не защищает от подделки и не является доказательством физического присутствия. Одноразовость устраняет повторное использование кода, но не заменяет антифрод, подтверждение продавца или сверку покупки.

## Изменения и аудит

PATCH организации/квеста требует `version`; несовпадение возвращает 409. Изменение, повышение версии и аудит атомарны. Импорт OSM также повышает версию обновлённых карточек, защищает места с владельцами и позволяет подписывать событие внутри транзакции импорта. Callback аудита синхронный; его ошибка откатывает импорт.

Аудит содержит actor, action, target, метаданные, request ID, предыдущий и текущий HMAC. Цепочка и её сохранённая вершина проверяются при старте и через административный API. Старые неподписанные записи v1 подписываются с меткой `legacyUnsigned`, что **не доказывает их историческую достоверность**. Функция `verifyAudit` принимает внешний expectedHead для контроля сохранённой вершины; автоматического внешнего anchoring в поставке нет. Скомпрометированные ключ и база позволяют переписать историю, поэтому для enterprise нужен независимый неизменяемый журнал/контрольная точка.

## Команды

Один игрок состоит в одной команде, команда относится к одному городу. Координаты выдаются только её участникам, при явном согласии пользователя, совпадении города и свежести ≤60 секунд. Интерфейс опрашивает состояние раз в 8 секунд, пока вкладка видима. Онлайн-индикатор отражает свежесть GPS. Общий результат учитывает публичные квесты города, выполненные после вступления. При выходе участника его вклад исчезает из текущего счётчика; при уходе владельца выбирается другой владелец и меняется приглашение.

## API

Городские GET-запросы принимают `?city=almaty|astana`, создание — `city_id`. По умолчанию используется Алматы. Время в JSON — Unix milliseconds.

| Путь | Операции |
| --- | --- |
| `/api/config`, `/api/health`, `/api/ready`, `/api/me` | GET конфигурации, liveness/readiness и сессии |
| `/api/register`, `/api/login`, `/api/logout` | POST аккаунта/входа/выхода; login может вернуть `mfaRequired` + `challengeId` |
| `/api/auth/mfa/login`, `/setup`, `/enable`, `/disable` | POST второго этапа входа и управления MFA (все под `/api/auth/mfa`) |
| `/api/auth/security`, `/api/auth/sessions/revoke` | GET безопасности; POST отзыва по `sessionId` или `allOthers` |
| `/api/organizations?q=&bbox=&offset=`, `/api/quests` | GET каталога до 500 записей/страница и заданий |
| `/api/progress`, `/api/location`, `/api/explored` | GET прогресса; POST/DELETE позиции; DELETE ячеек |
| `/api/quests/:id/complete` | POST прохождения с `code`, если нужен |
| `/api/manage?search=` | GET кабинета города с проверкой владельца |
| `/api/manage/organizations`, `/api/manage/quests` | POST; PATCH `/:id` с `version` |
| `/api/manage/quests/:id/tokens`, `/redemptions` | POST кодов; GET истории под тем же квестом |
| `/api/manage/rewards`, `/api/manage/users/:id` | GET статистики; PATCH роли/блокировки (admin) |
| `/api/manage/osm`, `/api/manage/osm-query` | POST импорта; GET запроса для выбранного города |
| `/api/team`, `/api/team/join`, `/api/team/sharing` | GET/POST/DELETE команды; POST вступления; PATCH согласия |
| `/api/admin/metrics`, `/api/admin/audit`, `/api/admin/audit/verify` | GET метрик, истории (`before`, `limit`) и проверки HMAC |

## Эксплуатация и пределы

Readiness возвращает 503 при graceful shutdown; новые записи при завершении отклоняются. Структурированные HTTP-логи содержат request ID, метод, статус, длительность, без query, cookie или тела. Метрики в памяти — ограниченное окно последних 5 000 длительностей и счётчики процесса. Постоянного внешнего мониторинга нет.

Резервирование использует SQLite online API, приватный временный снимок и AES-GCM; restore проверяет manifest/hash/SQLite и создаёт новый файл. Production-настройки, расписание резервирования и критерии восстановления описаны в [OPERATIONS.md](OPERATIONS.md).

Однопроцессный SQLite и синхронные запросы ограничивают параллелизм; импорт/проверка длинного аудита может задерживать обработку. Нет распределённых блокировок, многорегиональности, автоматического failover, SSO/OIDC, email recovery, POS или платежей. Миграция на PostgreSQL/PostGIS, событийный транспорт вместо polling, независимый аудит и инфраструктурная приёмка остаются последующими этапами.
