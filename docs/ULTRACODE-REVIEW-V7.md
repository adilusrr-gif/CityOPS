# Глубокое ревью City Quest 0.6 → 0.7

Дата: 24 сентября 2026. Проверены исходники предыдущего архива `city-quest-v6-product-stability.zip` и рабочая версия. Это ревью кода с воспроизведением дефектов, а не независимая сертификация или испытание развёрнутого production.

P1 — высокий приоритет до выпуска; P2 — функциональная надёжность, приватность и целостность; P3 — ограниченная оптимизация. Все перечисленные исправления включены в 0.7. Итоговые результаты прогонов находятся в [VALIDATION.md](VALIDATION.md).

## Оптимизации

- **R18 / P3:** `/api/promotions` выполнял до 51 последовательного SQL-запроса на 50 карточек. Теперь один SQL read model со связанными тарифами. Проверены число запросов, downgrade, refund и disabled-пользователь. Это сокращение round trips, не доказательство production throughput; оконное ранжирование и точные totals требуют измерений на большой БД.
- **R19 / P3:** удалён избыточный grouped base64 regex перед точным decode→encode. Строгость проверяется на пробелах, NUL, base64url, padding, pad bits, предельном размере. Локальная медиана парсера 3 МиБ: 29,64 → 5,67 мс, 15 прогонов. Не HTTP- или нагрузочный тест сервиса.
- **R20 / P3:** SQLite startup больше не загружает всю историю аудита в JS-массив и не проверяет подписанную цепочку дважды. Потоковая обработка остаётся в транзакции; прежние проверки цепочки, mixed history и rollback сохранены. Полный HMAC-обход по-прежнему линейный и требует измерения времени старта на реальном объёме.

## Проверенный объём и ограничения

Рассмотрены auth/MFA/SSO и отзыв сессий, права на организации и личные задания, одноразовые награды, команды, территории, фото/модерация/голоса, billing/entitlements/refund, границы AI, SQL pool и snapshot, backup/restore/import, HTTP drain, mobile transport, поиск и PWA. В этих областях не найдено дополнительных подтверждённых обходов после исправлений; это не гарантия отсутствия иных дефектов.

Схемы остаются SQLite 5 / PostgreSQL 6: исторические SQL-миграции не переписываются. Старые ключи, прогресс и финансовые ledgers сохраняются. Новые API-проверки отклоняют нештатные типы JSON; обычные строковые коды и ID совместимы.

Не испытаны native PostgreSQL contention/failover, Kubernetes rollout и восстановление, production TLS/DNS/SSO, живой AI/эквайринг и реальные телефоны. Внешний AI нельзя заставить забыть уже переданные данные отменой локального запроса; новые проверки останавливают следующие стадии. Квота неопределённо потраченного запроса не возвращается автоматически.

Каталог OSM не гарантирует полноту, GPS — присутствие, фотоголоса — отсутствие накрутки. Горный пример остаётся draft до полевой проверки. Медиа в SQL и пилотная ручная оплата сохраняют описанные продуктовые границы. Общий native-код не является подписанным APK/IPA.

Для выпуска обязательны актуальный native PostgreSQL CI, проверка целевого контейнера, нагрузка и восстановление на площадке, настройка реальных доменов/IdP и проверка телефонов. См. [PRODUCT-LAUNCH.md](PRODUCT-LAUNCH.md). GitHub недоступен по административному ограничению: push не выполнен; результат передаётся архивом.
