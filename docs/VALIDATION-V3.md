Пропущенный тест проверяет одновременную блокировку строки и `SKIP LOCKED` на **двух самостоятельных PostgreSQL-соединениях**. ## Что подтверждают SQL и HTTP тесты

Локальный enterprise-набор выполнялся на **настоящем PostgreSQL SQL engine через PGlite/WASM**, не на SQL-моках. PGlite сериализует транзакции; локальный результат **не доказывает native concurrency, репликацию или failover PostgreSQL**. Дополнительный тест использует реальный `pg.Pool` по TCP к PGlite Socket, проверяя адаптер, транзакции, savepoints и парсинг чисел.

Проверены:

- чистые миграции и checksum: 13 128 карточек, 24 квеста, 0 пользователей; повторный seed не дублируется;
- перенос v2 SQLite: все таблицы, ID, работоспособные scrypt-пароли, MFA, recovery, XP, команды, позиции, одноразовые коды и исходные подписи HMAC;
- отказ переноса при неверных ключах, повреждении или неподписанной истории; запрет перезаписи непустой цели;
- transactional rollback/savepoints, аудит и вершина цепочки, общий rate budget, точность bigint;
- награды, повтор одного completion, лимит кампании, токен, расписание, GPS/прогресс/карточки другого города;
- владение бизнесом, модерация, приватные поля, конфликты 409, отзыв сессий/мобильных продолжений, атомарный OSM-импорт;
- команды до 20 игроков, передача владения, приглашения, согласие на координаты и свежесть;
- OIDC с локальным mock IdP, который подписывает настоящие RS256 ID tokens и публикует JWKS: nonce/state/cookie binding/PKCE/signature/issuer/audience/expiry;
- native обмен кода с verifier, однократность и отсутствие bearer в URL, сохранение локальной MFA после SSO, точный issuer+subject и отсутствие email-autolink;
- парольный и резервный MFA-вход, конкурентные подтверждения, лимит попыток, отзыв и idle expiry;
- итоговая конфигурация TLS **настоящего `pg.Client`**: запрет weak modes/URL-override/hostname callback bypass;
- bounded cleanup: сроки, свежие записи, независимый commit таблиц, ограничение 1 000 записей/операцию;
- SQLite-операторы не создают ошибочную локальную базу при заданном PostgreSQL `DATABASE_URL`.

Две HTTP-реплики с общей базой проверены отдельно: cookie входа на A работает на B, позиция A используется при completion B, повторное начисление отсутствует, команда общая. После закрытия A сессия/прогресс B работают; drain даёт 503 для readiness и новых мутаций. Native CORS проверен для iOS/Android, чужой origin отклоняется; web получает cookie, native — bearer. Это остановка экземпляра приложения в тесте, **не испытание потери серверного узла или primary БД**.

Chromium 134: desktop 1440 × 980, мобильные ширины 390 и 320 px. Проверены реальные карты Алматы/Астаны, Three.js, границы/туман, GPS, городские данные, мобильная регистрация бизнеса, отправка организации/квеста, одобрение и публикация администратором, прохождение игроком с начислением XP. Геолокация эмулирована. Реальные ответы OpenFreeMap передавались через HTTP-клиент тестовой среды из-за её ограничений браузерной сети; география не подменялась.

Кеш PWA содержит только перечисленные статические файлы. API, данные аккаунта, квестовые ответы, координаты и награды в него не записываются. Offline показывает оболочку и отсутствие сети; повторное подключение восстанавливает работу без выдуманного прогресса.

Android/iOS-проекты созданы командами Capacitor и синхронизированы после последнего изменения исходников. Bundle собран из общего `public/`. **APK/AAB/IPA, iOS Simulator, Android Emulator и реальные устройства не проверялись:** в среде нет требуемого JDK 21/Android SDK/Xcode. Включённый пример указывает на `https://cityquest.example`, перед использованием нужен rebuild со своим HTTPS API.

## Что ещё нужно испытать на целевой площадке

Не выполнены Docker runtime/build, Kubernetes admission/scheduling, TLS/DNS/реальный корпоративный IdP, native PostgreSQL row-lock contention, отказ primary/зоны, WAL/S3 backup и PITR, большая нагрузка с записью, полевые координаты и физические мобильные устройства. RPO/RTO в runbook — цели приёмки, не измеренные гарантии. Старые файлы `load-test-almaty.json` и `load-test-astana.json` относятся к SQLite **версии 0.2**, их нельзя переносить на производительность 0.3 PostgreSQL.

Порядок приёмки описан в [PRODUCTION-HA.md](PRODUCTION-HA.md), [SSO.md](SSO.md) и [MOBILE.md](MOBILE.md). Публикация в магазинах и реальное развёртывание требуют инфраструктуры и полномочий владельца.
