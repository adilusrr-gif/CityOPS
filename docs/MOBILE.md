# Один клиент: браузер, PWA, Android и iOS

Версия 0.8.0 использует общие `public/app.js`, `map.js`, `platform.js`, модули игровых экранов и CSS. Capacitor добавляет разрешения GPS, события жизненного цикла приложения и системное окно SSO. Логика квестов, приключений, территорий, фотоконкурсов и начисление XP остаются на сервере. Native-клиент подключается к **enterprise API**; локальный SQLite режим поддерживает браузер и PWA.

В архив входят настоящие проекты Android Studio и Xcode, Gradle wrapper, Swift Package Manager, исходники плагинов через фиксированный `package-lock.json` и собранные web assets. **APK/AAB/IPA не выпущены, подписи и публикации в магазинах нет.** Для исходников не требуется переписывать интерфейс на Kotlin/Swift, но проверка WebGL, GPS и SSO на реальных устройствах остаётся обязательной перед выпуском.

## Сборка под свой сервер

Сначала разверните enterprise backend с доступным HTTPS origin и действительным TLS-сертификатом. Native-клиент не использует cookie сессии. В конфигурации backend разрешите точные native origins: `capacitor://localhost` и `https://localhost` (см. production env и SSO инструкцию). Не используйте wildcard CORS.

```bash
cd mobile
npm ci
CITYQUEST_API_ORIGIN=https://your-cityquest.example npm run sync
npm run android
# Xcode доступен на macOS:
npm run ios
```

PowerShell:

```powershell
cd mobile
npm ci
$env:CITYQUEST_API_ORIGIN = 'https://your-cityquest.example'
npm run sync
npm run android
```

`CITYQUEST_API_ORIGIN` — origin, без `/api`, других путей, query, пароля и HTTP. Эта публичная настройка вшивается при сборке; секреты сервера в неё не передаются. Архивный sample bundle использует зарезервированный `https://cityquest.example`: это пример, а не работающий адрес. **Перед запуском на телефоне выполните `sync` со своим адресом.** Новый адрес требует пересборки приложения.

`server.url` не задан. UI, MapLibre и Three.js входят в пакет; произвольный удалённый сайт внутри WebView не загружается. Геоданные карты остаются сетевыми и требуют доступа к `tiles.openfreemap.org`. CSP разрешает подключение только к origin API и этому источнику карты. Авторизация без интернета и офлайн выдача наград не поддерживаются.

## Среда и релиз

Зафиксированы Capacitor core/CLI/Android/iOS **8.5.2**, App **8.1.1**, Browser **8.0.4**, Geolocation **8.2.2**, esbuild **0.28.2**. Установка воспроизводится через `npm ci` в `mobile`, отдельно от пакетов backend.

- Node.js 24+ для этого проекта.
- Android Studio 2025.2.1+, установленный SDK 36 и JDK из Android Studio. Android min SDK 24; нужен обновлённый Android System WebView 109+. Проект `mobile/android`; debug: `./gradlew assembleDebug`. Release AAB создайте через Android Studio с собственным upload key; ключи в репозиторий не добавляйте.
- macOS и Xcode 26+; проект `mobile/ios/App/App.xcodeproj`, SPM зависимости подтянутся из lock/package конфигурации при открытии. Deployment target приложения iOS 16.4+. Укажите свой Apple Team и уникальный bundle identifier; затем Product → Archive. Apple Developer аккаунт, provisioning и signing предоставляет владелец приложения.
- Начальный app ID: `kz.cityquest.app`; перед публичным выпуском замените его на принадлежащий вам идентификатор одновременно в Capacitor, Android namespace/applicationId и Xcode Bundle Identifier. `cityquest` — callback scheme в обеих платформах, его значение должно совпадать с backend конфигурацией SSO.

Официальные источники: [Capacitor environment](https://capacitorjs.com/docs/getting-started/environment-setup), [Geolocation](https://capacitorjs.com/docs/apis/geolocation), [App deep links/lifecycle](https://capacitorjs.com/docs/apis/app), [Browser](https://capacitorjs.com/docs/apis/browser), [workflow](https://capacitorjs.com/docs/basics/workflow).

## Вход и защита данных

Обычный браузер использует HttpOnly cookie. Native API запросы отправляют `X-CityQuest-Client: native`, `Authorization: Bearer …` и `credentials: omit`. Bearer и PKCE verifier находятся только в JavaScript памяти. Они не пишутся в localStorage, Preferences, IndexedDB, файл или Android backup. Полное завершение/перезапуск приложения требует повторного входа; сворачивание приложения токен не сохраняет на диск. Отзыв сессий, idle timeout, MFA и роли контролируются backend. В localStorage хранится только выбранный город.

SSO открывается плагином Browser (платформенный браузер, без внедрения паролей IdP в интерфейс). Native генерирует случайный verifier и S256 challenge. Backend возвращает `cityquest://auth/callback?code=…`; клиент проверяет точную схему/host/path, обменивает одноразовый код с verifier. Bearer в URL отсутствует. Повторная доставка callback через launch URL и appUrlOpen не запускает второй обмен и не показывает ложную ошибку во время первого. Закрытие процесса во время SSO теряет verifier — повторите вход. Custom scheme может перехватить другое установленное приложение, но без verifier оно не сможет обменять код; для публичного выпуска можно дополнительно внедрить Universal/App Links с принадлежащим вам доменом.

Web SSO локальный MFA challenge приходит во fragment, который сразу очищается из адресной строки. Для SSO аккаунта без локального пароля интерфейс показывает защиту провайдера, а не форму пароля. MFA требования для администратора смотрите в `SSO.md`; наличие SSO само по себе не повышает роль.

## Геолокация и жизненный цикл

GPS запускается по кнопке и после системного разрешения. Отказ, приблизительная геопозиция вместо точной, выключенная системная геолокация и тайм-аут показывают отдельные русские подсказки; после изменения настройки нажмите «Моё положение» повторно. При сворачивании/скрытии вкладки, смене города или выходе watcher останавливается; после возврата он не запускается без действия пользователя. Учтена гонка, когда пользователь свернул приложение во время системного запроса разрешения или до выдачи watch ID. Повторные события WebView и ОС объединяются: возврат ожидает локальную остановку watcher. Потеря сети также останавливает GPS локально; восстановление соединения его не запускает. Нет фонового location service и `ACCESS_BACKGROUND_LOCATION`.

Удаление последней серверной позиции после остановки выполняется по сети best effort: при потере сети запись живёт до серверного срока удаления. Нативный GPS не доказывает физическое присутствие и может быть подменён. Координаты и данные аккаунта требуют корректного раскрытия в Google Play Data safety / App Store privacy; подготовьте опубликованную политику приватности и проверьте реальные SDK перед подачей.

## Приключения и фотографии v0.5

Мобильный клиент использует те же маршруты, командные зоны, личный прогресс и фотоконкурсы, что и браузер. Для отметки места и отправки фото требуется свежая геопозиция; при отсутствии сети запись не ставится в офлайн-очередь и XP не начисляется локально. Фото передаётся серверу для проверки формата и модерации; приватные изображения не должны попадать в PWA-кэш или постоянное хранилище токенов. Изменение доступа после удаления/модерации проверяется API.

Для текущего клиента нужен backend v0.8: PostgreSQL-схема 6, либо SQLite-схема 5 для браузера/PWA. Номера схем сохранены относительно v0.6; совместимость смешанного rollout проверяется на staging до публичного обновления. Обновите backend по [PRODUCTION-HA.md](PRODUCTION-HA.md#обновление-с-v07-на-v08), затем пересоберите клиент и выполните `sync`. Native-слой не обновляется публикацией новых серверных файлов: пользователю потребуется новая сборка приложения. Инструкции модератора и ограничения снимков — в [PHOTO-CONTESTS.md](PHOTO-CONTESTS.md).

На реальных Android/iOS дополнительно проверьте выбор фотографии, отказ в доступе, ориентацию портретного кадра, ошибку формата/размера, разрыв сети во время загрузки, просмотр приватного снимка через авторизованный API, смену аккаунта и отсутствие старого изображения после выхода. Наличие браузерного теста не подтверждает работу системного выбора файлов на конкретном телефоне.

## PWA

В браузере приложение можно установить из меню браузера. `manifest.webmanifest` содержит название, иконки, standalone режим. Service Worker кэширует только явный список статических файлов UI и движков карты. Он не перехватывает `/api`, SSO callbacks, запросы с query, внешние tiles и mutations; не кэширует аккаунты, GPS, токены или результаты запросов. Без сети показывается shell и сообщение об отсутствии соединения. Новая версия shell активируется после закрытия старых вкладок; принудительной перезагрузки во время ввода кода нет.

## Проверка перед релизом

Автоматические тесты `tests/mobile-client.test.mjs` проверяют границы транспорта, отсутствие сохранения токена, отмену GPS и запрет кэширования API. Browser QA отдельно проверяет общий интерфейс, города и PWA cache. Выполнены `cap add android`, `cap add ios`, `cap sync` и esbuild сборка. В проверочной Linux-среде 4 октября 2026 есть Java 21 runtime, но отсутствуют `javac`, Android SDK/adb/sdkmanager и Xcode; нативная компиляция, физические устройства, entitlement/signing, доставка custom scheme ОС и store review здесь не проверены.

Практический smoke на каждом устройстве: регистрация/пароль/MFA, SSO отмена и возврат, app kill во время SSO, logout и отзыв сессии со второго устройства, permission denied/approximate/precise, сворачивание во время permission prompt, смена города при GPS, map rotate/zoom/3D, 320px экран и клавиатура, медленная сеть при выдаче награды, перезапуск без сохранённого bearer. Эти проверки являются релизным этапом, а не заявленным результатом симуляции в браузере.

### Выбор фотографии в v0.5

Фото выбирается через системный обработчик HTML file input. В iOS добавлены русские `NSCameraUsageDescription` и `NSPhotoLibraryUsageDescription` для тех вариантов системного выбора, которые запрашивают камеру или фототеку; ключи сами не предоставляют доступ. Приложение не перечисляет всю фототеку. Android использует системный file chooser Capacitor, без разрешений на всю память устройства. Наличие пункта камеры зависит от платформы; можно заранее снять фото и выбрать готовый файл. Камера, отказ разрешений и форматы HEIC/JPEG требуют проверки на реальном устройстве. Сервер принимает только JPEG/PNG/WebP.

Требования к строкам назначения доступа: [Apple: описания доступа к приватным данным](https://developer.apple.com/library/archive/qa/qa1937/_index.html).


## Публичная сборка v0.8

Настройте реальные контакты и правовые документы на backend, пройдите [PRODUCT-LAUNCH.md](PRODUCT-LAUNCH.md) и пересоберите приложение со своим HTTPS origin. Для собственного стиля карты передайте `MAP_STYLE` и `MAP_RESOURCE_ORIGINS` с тем же списком tile/sprite/glyph origin, что на сервере; проверьте загрузку карты в WebView. Примерный origin архивного bundle и CI предназначен для проверки сборки и не является выпущенным сервисом.

Отказ из-за насыщения HTTP/SQL очереди означает временную недоступность; клиент не должен повторно отправлять оплату, голос или награду без проверки результата. Не включайте автоматические повторные mutation-запросы поверх сетевой ошибки. Чувствительные ответы, фотографии и bearer остаются вне PWA-кэша. Браузерная проверка общего UI не подтверждает нативную доставку разрешений или подпись магазина.


## Подготовка универсального приложения к выпуску

Общий адаптивный клиент работает в проектах Android и iOS; это одна кодовая база, но два отдельных платформенных пакета. Android APK/AAB и iOS IPA требуют своих инструментов сборки и проверки. Сборка web assets и `cap sync` не заменяют нативную компиляцию.

Для production-сборки используйте явный release-шаг:

```bash
cd mobile
CITYQUEST_API_ORIGIN=https://YOUR_DEPLOYED_API_HOST npm run release:prepare
# Проверка уже синхронизированных ресурсов:
CITYQUEST_API_ORIGIN=https://YOUR_DEPLOYED_API_HOST npm run release:check
```

Замените `YOUR_DEPLOYED_API_HOST` адресом своего реально развёрнутого API. Команда `release:prepare` заново собирает общий UI, выполняет Capacitor sync и проверяет выбранный HTTPS origin во всех трёх копиях (`www`, Android, iOS), совпадение shared assets и отсутствие remote server URL/mixed content. Зарезервированные `.example`, `.test`, `example.com` и локальные адреса блокируют release-проверку. Обычный `sync` по-прежнему допускает демонстрационную сборку для CI; её нельзя выдать за готовый клиент работающего сервиса. Проверка не обращается к API и не подтверждает доступность backend, CORS, права на домен, подпись или требования магазинов.

При возврате в карту/квесты и восстановлении сети клиент обновляет данные только GET-запросами. Активная форма, выбранная фотография, ввод с клавиатуры и остальные экраны сохраняются; постоянная строка состояния предлагает обновить данные явно. Ошибки остаются с кнопкой повтора. Завершённые действия, голоса, награды и загрузки не повторяются автоматически. При полном отсутствии сети GPS остановлен, а точка на сервере удаляется по обычному сроку хранения.

Навигация на узком телефоне прокручивается горизонтально внутри панели, не расширяя всю страницу. Отступ при прокрутке учитывает safe area; максимальная высота диалога использует динамическую высоту viewport там, где она поддерживается. Работа реальной клавиатуры, вырезов экрана, native file chooser и системных разрешений остаётся в device smoke-check.

Добавлены поведенческие регрессии: `tests/mobile-client.test.mjs`, `tests/mobile-ui-recovery.test.mjs`, `tests/mobile-release.test.mjs`. Они проверяют настоящий JS-код с контролируемыми API/OS-подменами; не эмулируют работу ОС и не заменяют устройство. В текущей среде браузерная визуальная проверка localhost также заблокирована, поэтому CSS не заявляется как визуально проверенный на телефоне.
