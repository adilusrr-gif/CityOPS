Метка относится к базе источника, а не к дате проверки каждого заведения. На чистой базе после seed и обоих импортов получается **8 346 карточек Алматы и 4 782 карточки Астаны; всего 13 128 карточек и 24 квеста**. Две дополнительные карточки Алматы — редакционные точки без OSM ID. Эти числа не означают количество уникальных действующих бизнесов.

`datasets/manifest.json` содержит точные границы, запросы, даты базы источника, размеры файлов и SHA-256. Исходники снимков: `datasets/almaty-osm.json` и `datasets/astana-osm.json`.

|---|---:|---:|---:|---:|
| Алматы | 76.70 | 43.02 | 77.20 | 43.45 |

Это операционные прямоугольники города и окрестностей; административные границы не загружены. Приложение не гарантирует покрытие всех земель, административно относящихся к городу.

Выбираются именованные узлы, линии и отношения с `amenity`, `shop`, `tourism`, `office`, `craft` или `leisure`; для площадных объектов используется центр Overpass. Точная воспроизводимая функция запроса — `osmQuery(cityId)` в `src/osm.mjs`; `OSM_QUERY` сохранён для совместимости и означает Алматы. В компактном файле сохранены OSM type/ID, координаты/центр, названия, классификация и адрес; контактные и прочие теги исключены.

### Обновление

В PostgreSQL-режиме используйте импорт выбранного города в административном кабинете. Следующие CLI-команды обслуживают локальную SQLite-базу; при заданном `DATABASE_URL` изменение через этот CLI отклоняется, чтобы не обновить другую базу случайно.

```bash
npm run import:osm -- --city astana --query
npm run import:osm -- --city astana
npm run import:osm -- --city almaty --file datasets/almaty-osm.json
npm run import:osm -- --city astana --file datasets/astana-osm.json
```

При загрузке из сети исходный ответ записывается в `data/osm-last-import-<city>.json`; он не включается в архив с пользовательскими данными. Обновлённый снимок поставки следует отдельно сократить до разрешённых тегов и пересчитать manifest. Публичный Overpass — внешний сервис без предоставляемого проектом SLA; для регулярной эксплуатации нужны расписание, лимиты, повторные попытки и собственный договор/инфраструктура по нагрузке.

Импорт транзакционный. Проверяются город, границы, конечные координаты, имя и положительный целочисленный OSM ID; ответ с `remark` отклоняется как потенциально неполный. Глобальный ключ `node/ID`, `way/ID` или `relation/ID` не дублируется между городами. Одинаковый OSM ID обновляет существующую карточку. Карточки с назначенным владельцем (`owner_id`) пропускаются и не перезаписываются. Данные, не пришедшие при очередной загрузке, автоматически не удаляются.

Обновление OSM увеличивает `version` карточки и устанавливает `updated_at`: открытая до импорта форма при сохранении получает конфликт 409 и должна загрузить свежую версию. Импорт поддерживает синхронный `onImported(report)` внутри той же транзакции; ошибка записи аудита откатывает карточки и отчёт импорта. CLI подписывает событие `osm.import` серверным ключом аудита через этот callback. Запускайте его с теми же настройками ключей, что и сервер; в production действуют проверки production-конфигурации.

### Ограничения качества

- Полнота, актуальность, часы работы, наличие бизнеса по адресу и доступность входов не гарантируются.
- Несколько OSM ID могут обозначать одно место; автоматическая дедупликация работает только по типу/ID. Например, в источнике встречаются отдельные узел и контур одного здания.
- Центр полигона может находиться внутри здания, ограждённой или платной территории. Он не считается пешеходным входом или целью навигационного маршрута.
- Каталог не содержит все POI города: фильтр исключает неназванные объекты и объекты с другими тегами. Наличие объекта на базовой карте не означает наличие отдельной карточки в каталоге.
- OSM ID и имена могут меняться. Новая карточка источника не доказывает смену владельца или открытие бизнеса.
- Публичный запуск предполагает модерацию, исправление дублей, проверку заявок владельцев и проверку игровых точек на местности.

## Стартовые квесты

Оба набора — придуманные редакционные задания у реальных мест в `src/seed.mjs`. Партнёрства, коммерческие акции и награды от организаций **не заявлены**. Награда — виртуальный опыт приложения. В каждом городе 8 общих и 4 личных задания; личные стартовые задания доступны каждому игроку отдельно, они не являются персональным назначением конкретному пользователю.

### Алматы

Сохранён набор v1 из 12 заданий: парк Панфиловцев, Вознесенский собор, Зелёный базар, Арбат, театр имени Абая, площадь Республики, Центральный государственный музей, Дворец Республики, колоннада парка Первого Президента, вход в ботанический сад, Центральный парк, музей Кастеева.

Десять мест имеют конкретный OSM ID. Арбат и площадь Республики — редакционные точки с ориентировочными координатами. Для парков и площади у Дворца Республики использованы точки подхода, не гарантированно проверенные входы. Радиус — 180 м. Метка `seed_version` и все старые ID сохраняются; повторное открытие базы не дублирует задания и не сбрасывает прогресс.
